# Issue 41: comparison with official Home Assistant implementation

Compared our current TCP client with Kinachi249/pycync tag v0.5.0, the dependency
pinned by Home Assistant core tag 2026.9.1. This identifies the version in that HA
release, not independent verification of the reporter's installed HA version.

Sources:
- https://github.com/home-assistant/core/blob/2026.9.1/homeassistant/components/cync/manifest.json
- https://github.com/Kinachi249/pycync/tree/v0.5.0/pycync/tcp

## Session lifecycle

| Area | pycync v0.5.0 | Current plugin |
| --- | --- | --- |
| Host | cm-sec.gelighting.com, TLS 23779 | cm.gelighting.com, TLS 23779, optional plain TCP fallback |
| Login readiness | Waits for LOGIN message before requests | Socket plus fixed settling delay |
| Heartbeat | Every 20 seconds | Every 180 seconds |
| Disconnect frame | Parses high nibble 14 as DISCONNECT; clears login readiness, closes transport, reconnects after 10 seconds | Logs 0xe0 as unparsed; waits for socket close |
| Status acknowledgement | No explicit incoming PIPE acknowledgement located in tcp_manager/command_client | Sends 0x78 response |

The observed e0/03 packet is therefore a disconnect message according to this
reference. Code 03's specific cause remains unestablished. This supports session
invalidation immediately on receipt; it does not prove duplicate account sessions.

## Outbound encoding

pycync/inner_packet_builder.py generates a four-byte little-endian inner sequence,
increments it, and repeats it in state-changing command arguments. Our power/combo
builders use fixed zero bytes in these positions. pycync's embedded command suffix
uses 11 02 where ours uses 00 00. Its CT combo uses zero RGB bytes while ours uses
ff ff ff. These are concrete encoding differences, not yet proof of rejection.

pycync escapes inner 7e bytes before calculating the outer packet length. Our
power/combo builders assemble unescaped inner bytes with fixed outer lengths.
Incoming escaping was fixed earlier, but outgoing encoding remains different.

The reference parses message type, response flag, and version separately, while
our dispatch predominantly matches whole bytes. It validates inner checksums and
lengths; ours relies mainly on known offsets and bounds.

3. Assess endpoint/login/heartbeat differences separately; do not claim changing

4. Avoid another broad beta until packet and lifecycle tests cover these findings.

## Beta.6 controlled session comparison

Login now ends in `00001e`, and controller probes include the reference trailing
`0002` with an eight-byte payload. Login and probe fixtures were generated by
executing the downloaded pycync 0.5.0 builders with synthetic credentials.
Existing login blobs are rebuilt from stored authorization, including legacy
stores containing only the serialized packet; no new sign-in is required.

Incoming status packets no longer cause an application ACK. Controllers are
probed once per authenticated session (or when newly added to topology), rather
than before every query. Successful writes no longer schedule broad mesh refreshes.
Startup, periodic reconciliation and failure recovery queries remain. Bounded
write retries and OFF cancellation remain; this is not a wholesale port of pycync.

Validation: 38 tests and lint pass. Session stability still requires live testing.
